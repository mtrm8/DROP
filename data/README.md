# Bunker data pipeline

`npm run bunker:fetch` queries API-Football (API-Sports v3) for today's not-started fixtures, recent historical results, confirmed or projected lineups, season statistics for starting players and the `Goals Over/Under → Over 2.5` market. It requires `API_FOOTBALL_KEY` and writes private working input to ignored `data/bunker-live.json`. `BUNKER_TIMEZONE` defaults to `Asia/Jerusalem` and defines "today"; `BUNKER_LEAGUES` can add comma-separated fallback league IDs when no headline fixture is upcoming. The headline pool is Nations League, UEFA club competitions and the top five domestic leagues. The provider's fixture list determines what actually exists on a given day; the script cannot guarantee a price or lineup the provider has not published.

The strict selector requires at least three home/away results per team from the past year and season stats for at least nine starters per side. It uses confirmed XIs when available; otherwise the last starting XI is marked **projected**, never confirmed. A confirmed XI with more than four changes from the previous XI is excluded. A selection requires a price no more than 12 hours old and positive individual edges; the combined same-bookmaker accumulator must clear 4%. Goals/assists, minutes, shots and key passes appear as player context; the Poisson model uses historical goals, not an uncalibrated player-strength adjustment. A match can still appear on the clearly labelled watchlist when these stricter pick requirements cannot be met.

`BUNKER_DATA_FILE=data/bunker-live.json BUNKER_REQUIRE_LIVE=1 npm run bunker:generate` validates the fetched input and writes `components/bunker/generatedReport.json`. `npm run build:static` exports to `out/`; `npm run bunker:test` verifies the model and selection rules. `npm run build` uses the synthetic local demo input by default; it **must not** be used for live publication.

The **committed** GitHub Actions workflow `.github/workflows/bunker.yml` currently runs every six hours (`0 */6 * * *` UTC), with a manual `workflow_dispatch` trigger. It runs `node scripts/bunker-model.mjs`, which fetches and validates the data, builds `out/`, mirrors it into `public/`, and deploys that directory to `gh-pages`. Importing the model from tests or other scripts does **not** trigger publication. If the provider cannot be reached, the run publishes a **dated** "scan did not complete" report for the current day instead of aborting. Genuine build failures still abort publication. That status carries the reason the scan failed, distinguishing an invalid key (`HTTP 401`) from a quota issue (`HTTP 429`).

Each scan issues dozens of sequential calls, so it is written to survive partial failure. Rate-limited (`429`), server (`5xx`) and network responses are retried a few times with a growing pause, and any single fixture that still fails is skipped with a logged reason rather than aborting the run. One unreachable match can no longer cost the whole scan, and a run that keeps most of its fixtures publishes the rest as a watchlist instead of an empty report.
`scripts/postbuild-pages.mjs` also exports `out/bunker-data.json`. An open Bunker checks the public export every minute while a future Watchlist match is missing a confirmed XI or fresh price, every five minutes otherwise, and when the tab becomes visible. These checks do not call API-Football; a new provider response becomes visible only **after another workflow run deploys it**. Use Actions → Build and Publish Bunker Report → Run workflow for an immediate rescan when approaching kickoff.

Automated publication (`BUNKER_REQUIRE_LIVE=1`) requires real provider data that describes the **current local day** in the report's timezone and contains only fixtures that have not kicked off. It deliberately does *not* require a recent timestamp: a sequential scan of every fixture routinely runs far longer than the fifteen-minute window an earlier version imposed, and enforcing that window aborted long scans and left the site showing the previous day's report.

The Bunker shows a **scan snapshot**, and expires selections per match rather than as a whole: once one of today's matches kicks off it is dropped from the list, while any sibling match that has not started yet stays visible. A report is labelled by its own scan date, and the page distinguishes today's completed scan, provider outage and a report from an earlier day. It displays the next scheduled six-hour run. An open tab accepts a newer processed snapshot as soon as it is deployed and keeps still-upcoming, already-verified same-day fixtures visible if a later provider retry fails.

The checked-in input is **synthetic demo data**, not historical results. The report labels it as such. As an alternative to the built-in fetcher, `BUNKER_DATA_URL` (optional `BUNKER_DATA_TOKEN` bearer token) or `BUNKER_DATA_FILE` can supply a prepared JSON payload with this schema:

```json
{
  "mode": "live",
  "source": "Verified provider / dataset name",
  "asOf": "2026-09-26T12:00:00Z",
  "combinedOdds": 2.32,
  "picks": [],
  "results": []
}
```

For a report with picks, supply at least three **home** results for each home team and three **away** results for each away team, plus future kickoff, an `Over 2.5` price no more than twelve hours older than `asOf`, `lineup.homeKind`/`awayKind` (`confirmed` or `projected`) and `players` summaries for nine starters on each side. A starting XI is taken from the most recent of the last five results that actually published one, so a single fixture with missing lineup data no longer discards the day. `asOf` must fall on the current local day in the report's `timeZone` for automatic publishing. Use exact team names in `picks` and `results`.

Selection is a **same-bookmaker accumulator search**, and the bar applies to the combination, not to each leg: legs are only required to be individually positive, and the search ranges over two to four legs. Among combinations clearing the bar, major competitions take precedence, with expected edge breaking ties. Requiring every leg to clear 4% on its own was stricter than the maths needs — a real book rarely offers two legs at 4% each — and was the main reason flat days published nothing. The headline pool is UEFA Nations League, Champions League, Europa League, Conference League and the five largest domestic leagues. If none has an upcoming fixture today, Eredivisie, Primeira Liga and any leagues explicitly supplied in `BUNKER_LEAGUES` serve as fallback coverage; configured lower-tier leagues cannot displace a headline match. Prices must still be no more than twelve hours old, but no longer have to be stamped on the same calendar day, because the provider's update stamps lag fixture time by hours.

When no combination reaches the 4% combined edge, the report is **not** padded with picks that do not qualify. Instead every eligible fixture is remembered as it is scanned, and the report carries a `watchlist` of up to five matches. Fixtures are ranked by competition (and knockout stage / prominent national-team matchups), then available model evidence, then kickoff. A marquee match can remain visible ahead of a lower-tier match with a stronger historical model edge. Each row keeps whatever provider evidence was collected — an `Over 2.5` price where one was quoted — and a `note` naming the gate that prevented a strict selection. For watch-only context, three home and away venue results can produce the same historical-goals estimate as the strict model even when odds or season player statistics are pending; with sparse venue data, three recent results per team can support a separately labelled exploratory estimate. No probability is displayed without enough results. A last available price aged 12–48 hours is labelled **older** and never used to calculate an actionable market edge or select a pick.

When a combination *does* qualify, the report may still show up to three other headline fixtures in a separate watchlist beneath the selected picks. Those matches are not part of the accumulator. Head-to-head lookups run only for the matches actually displayed, to limit provider requests.

The report also carries a `scanNote` stating how many fixtures were eligible, how many were evaluated and why the rest were dropped, so "nothing qualified" is distinguishable from "nothing could be evaluated" and from "there were no matches today".

Watchlist cards carry official team crests supplied by the fixture endpoint (`media.api-sports.io`) and, where available, a recent five-game home/away venue sample: matches with three or more goals, goals scored and goals conceded. For displayed matches only, the scan also requests up to five finished head-to-head fixtures and labels their scorelines from today's home-team perspective; when that endpoint is empty, recent already-fetched team history is checked for direct meetings. Lineup panels distinguish confirmed starters, partial provider data, a prior XI **projected** for pre-match context and missing data; formation and player names appear only if the provider supplies them. The probability chart shows an estimate from actual results even when a new quote has not arrived; the market comparison is shown only with a disclosed price and never claims a current edge for an older quote. Missing evidence remains unavailable rather than being invented.

Data preparation, licensing, odds availability and opponent-strength adjustments depend on the upstream provider. The model takes the average of home goals scored and away goals conceded for the host's Poisson mean, and the converse for the visitor; it assumes independence between fixtures for accumulator probability. The combined price is a two-decimal rounding of one bookmaker's leg product, **not an independently verified offered accumulator price**. `goalBuckets` groups six or more goals in its final bin.

Configure repository secret `API_FOOTBALL_KEY` and optional variable `BUNKER_LEAGUES`, enable Actions with write access to repository contents, and keep GitHub Pages set to the `gh-pages` branch root. The generated client JSON is public: **never put API tokens or private data in source fields**.
